## Findings and implemented correction

### Low: shallow CI history assigns deployment dates to unchanged pages

All 102 production `<lastmod>` values are `2026-10-02`. The mechanism is reproducible: `tools/seo-inject.mjs:1364` obtains a clean source file's date from `git log -1 --format=%cI -- <file>`. The deployment job's `actions/checkout@v5` fetched only one commit because it omitted `fetch-depth`. At the shallow boundary, Git treats the entire snapshot as the first appearance of every file. An unrelated test commit therefore replaces genuine per-file history. [checkout defaults](https://github.com/actions/checkout)

For the unchanged `privacy.html` source, a local depth-one fetch of the current release returns `fb593aa 2026-10-02 test(analytics): isolate Ahrefs in browser regressions`. The complete repository history returns `512e31ae 2026-10-01 fix: restore Services and add Marine under Applications (#167)`. Uniform sitemap dates alone were only a warning; this reproduction establishes the defect.

Implemented: add `fetch-depth: 0` only to the `verify` job's checkout in `.github/workflows/verify.yml`. That job runs `verify:core`, which runs the production build and deploys `dist`. The `web_vitals` job runs the separate performance test command and does not deploy; its checkout remains unchanged. No modification to `fileLastModified` or generated sitemap output. Google uses modification dates only when consistently accurate and tied to significant content changes. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

Validation: `git diff --check -- .github/workflows/verify.yml` passed, YAML parsed successfully, and 14 existing build architecture and deployment batch tests passed. Full-versus-shallow history reproduction above passed. Production remains unchanged until the parent task releases these changes. Files regenerated by a build may still use their filesystem date when genuinely dirty; source-specific semantic dates remain a separate concern, not claimed fixed here.
