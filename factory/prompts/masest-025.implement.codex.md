        # Grill Gate

- Owner: maintainer.
- Decision source: maintainer selected conservative shared rendering; arbitrary author HTML is not authorized.
- Problem: stored newsletter bodies pass arbitrary HTML into staff preview and outbound email, allowing one writer’s markup to execute for another staff user.
- Out of scope: browser-only sanitizers, dependencies, authorization/sending/audience changes, editor rebuild, and unrelated CMS sanitization.
- Review failure: author HTML or unsafe URLs survive, supported formatting breaks, preview/email diverge, or gates fail.
- Riskiest assumption: existing saved newsletters do not require unsupported raw HTML.
- Smallest acceptable: one environment-neutral renderer that escapes author input and emits only controlled formatting and URLs.

# Context

Newsletter preview uses `innerHTML`, and the same rendered body feeds outbound email. Trusting all staff-authored raw HTML is unsafe. Sanitization must happen in the shared renderer so browser and server output remain identical.

# Acceptance Criteria

- User text and raw `<...>` are escaped.
- Renderer-generated paragraphs, headings, lists, blockquotes, code, strong, emphasis, underline, controlled size/color spans, cards, links, and images remain supported.
- Links allow only `https:`, `http:`, `mailto:`, `tel:`, and root-relative paths.
- Images allow only `https:`, `http:`, and root-relative paths.
- Reject `javascript:`, `data:`, protocol-relative, control-character, quote-breaking, and malformed URLs.
- External links generated by the renderer receive `rel="noopener noreferrer"`.
- Author input cannot emit `on*`, author-controlled `style`, `script`, `iframe`, `object`, or SVG markup.
- Preview and outbound email consume the same renderer output.
- Tests cover attacks, supported syntax, malformed/empty input, Unicode/ampersands, and relative/external URLs.
- All frontmatter verification commands pass; mark row 025 `DONE` afterward.

# Constraints

- Scope changes to `js/newsletter-render.js`, focused renderer tests, optional preview safe-output wiring in `js/admin/newsletter.js`, and row-025 status.
- Do not add npm dependencies or browser-only DOM sanitization.
- Do not change newsletter permissions, delivery, scheduling, recipients, editor behavior, or unrelated CMS rendering.
- STOP if arbitrary HTML is required, saved content needs a migration decision, safety requires browser-only APIs, or renderer-owned card syntax accepts arbitrary attributes.
