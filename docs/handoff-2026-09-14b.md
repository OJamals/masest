**Security shape.** masest is public, and a fork PR runs the workflow file *from the fork*,
so it could target the runner and read everything the runner user can. Two locks:
1. PR events route to GitHub-hosted Ubuntu. `tests/build-architecture.test.mjs` → "the
   self-hosted runner only ever receives trusted events" fails any workflow that can be
   PR-triggered and reaches the trusted label without that guard, requires non-PR jobs to
   name `masest-trusted`, requires `--with-deps` to be gated to GitHub-hosted runners, bans
   `pull_request_target`, and bans a sub-daily blog cron. Mutation-checked: pointing the
   PR-triggered `verify` job straight at `masest-trusted` fails it.
2. Repo fork-PR approval raised from `first_time_contributors` to
   `all_external_contributors` (`PUT /repos/OJamals/masest/actions/permissions/fork-pr-contributor-approval`).

**Runner prerequisites live on the host, not in jobs.** The runner has no root, so a job
can never `apt-get`; PostgreSQL 16 and Chromium's system libraries are preinstalled there
(PR #163). It does **not** carry Google Chrome, `zip` or `unzip`.

## Traps this session paid for

- **Never `history.replaceState(null, …)` on admin.html** — it erases `admTabIndex`, and a
  later cancelled Back can no longer compute its distance home. Pass `history.state`.
- **Any new workflow that can run on `pull_request` must use the guarded `runs-on`
  expression.** The guard test enforces it; do not weaken the test.
- **A job that can land on `masest-trusted` must not run `playwright install --with-deps`
  unguarded** — the runner has no root. Gate it on `runner.environment == 'github-hosted'`.
- **Tests launch Playwright's bundled Chromium, never `channel: "chrome"`**, and never assume
  a CLI a minimal Linux host lacks (`zip`, `unzip`, `textutil`). Green on GitHub-hosted
  images and a Mac proves neither. `python3` is the one tool every runner has.
- **A PATH-restricted probe must link real executables.** `command -v python3` here is a
  pyenv shim (a bash script); under a bare PATH it dies with `env: bash: No such file or
  directory` and the probe tests nothing. Link `os.path.realpath(sys.executable)`.
- **Another agent edits this checkout live** (this session: SES production verification —
  `package.json`, `workers/marketing-email/*`, `functions/_lib/newsletter-delivery.js`).
  `git rebase --autostash` carries those edits through intact; commit by explicit path only,
  and verify pushes from a clean `git worktree` (symlink `node_modules`) so their unfinished
  work never colours a result.
- **Test walkers must judge shipped files only** — intersect with
  `git ls-files --cached --others --exclude-standard`. Local tools (graft, Claude
  worktrees, backups) create whole copies of the site inside the repo directory.
- **The last handoff's suspect commits for both spec failures were wrong**, and the 86 ms
  claim came from a probe sampling inside a microtask. Inference is not a trace.
- Support console at phone width hides `.site-support__detail` (with the close button)
  until a ticket is selected. Accounts opens on the Users console; the company drawer is
  under Businesses & approvals.
- `clippedDescendants` in the responsive spec measures descendants only, never the root.
  The sitewide `.adm-main .btn-sm` coarse-pointer `!important` rule beats low-specificity
  CSS injected by a mutation test.
- A runner appeared mid-session with no trace in this checkout, and minutes later PR #163
  for the same change. Ask the owner before targeting an unknown runner, and run
  `gh pr list` before building CI changes — a parallel session may already have.
