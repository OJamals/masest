## What shipped, with the numbers

### Product offers were contaminated across 8 of 15 pages

The marine line is not a separate catalog row: its variants hang off the same
`product_sku` as the industrial product they rebrand, separated only by `market`. `cr-hd`
owns `CRHD-1G/25G` and the "Marine Degreaser" `MDG-1G/25G` alike. `buildProductOffers`
filtered on `product_sku` alone while the buybar also filters on `market`, so the page
showed two sizes and the schema advertised four.

```
purgo    $144.99 -> $102.49      multiwash  $84.99 -> $46.49
hcr-t16  $112.49 ->  $68.49      descaler   $79.99 -> $47.99
cr2       $99.99 ->  $61.49      alumibrite $64.99 -> $38.49
cr-hd     $64.99 ->  $33.99      torque     $54.99 -> $46.49
```

**Offers are injected at the edge**, by `functions/_lib/product-offer-jsonld.js`. The static
`products/*.html` and `tools/seo-inject.mjs` contain none, and
`tests/full-qa-remediation.test.mjs:135` asserts `schema?.offers === undefined` for every
repo-side product page. A grep for "offers" finds nothing while the live page has them.

### Two checkout address errors, one of them a 502

Google verdicts "123 Main St, Brooklyn NY 11201" as `ACCEPT` and returns it **without a
ZIP+4**; ShipStation then answers `/rates` with `400 Address not found`. That escaped
`quoteCheckoutRates` as a bare `ShipStationError`, missed the `CheckoutFulfillmentError`
branch, and fell to `functions/api/shipping-rates.js:57` — a 502, **which Cloudflare replaces
with its own HTML page**. The buyer read "No shipping option is available for this address
and cart": a typo in a street number told them MASEST does not deliver to them. The mapping
now sits at `functions/_lib/checkout-shipping.js:371`. The comment at `:335` shows the same
class of bug was already caught once, on the packing step.

The apartment case is the reported one, and Google names the remedy in
`possible_next_action`. The client discarded it. It now names the field and opens and
focuses it (`js/checkout.js:389` `setSuiteOpen`, called at `:882`).

Phase split, timed against the real providers: Google validation **141-325ms**, ShipStation
carrier list **1.2-1.6s**, the rate call the remaining ~3s. The staged status copy is at
`js/checkout.js:849`. **Timing itself was deliberately not touched.**

### The registry carried buyer-facing copy that reached no page

Six fields — `concentration`, `process`, `boundary`, `verification`, `materials`,
`wastewater` — distinct for all 26 industries, rendered on none. And all ten supplemental
pages shipped one identical sentence while `distinct_scope` went unrendered. Main body copy

`.qa-local/registry-coverage.mjs` is how both were found: import the registry, walk every

### Review ratings bake without a credential in CI

Production `product_reviews` has **0 rows**, so no `aggregateRating` is missing today, and
`productSchema()` already omits the node deliberately when there is nothing to rate. The
defect was the pipeline: `build-reviews.mjs` runs as `preseo-inject` inside `prebuild`
inside `verify:core`, and that step had **no Supabase environment at all**. So it took its
fail-open path and wrote `{}` on every deploy, and would have kept doing so after the first
approved review.

It now reads the site's own `GET /api/reviews`. `stats.avg` comes from `aggregateStats()` at
`functions/_lib/reviews.js:101`, which applies the **identical**
`Math.round((sum / count) * 10) / 10` the tool used to apply itself, and the Worker
(`functions/api/reviews.js:28`) filters to `status = 'approved'` server-side. No credential in
CI, no schema change. `REVIEWS_BASE_URL` or `APP_URL` override the origin.

Proven end to end against a stub: 51 targets in, aggregates out, and `seo-inject` then emits
`ratingValue: 4.7, reviewCount: 12` into the multiwash Product node.
`tests/build-reviews.test.mjs` was mutation-tested — removing the zero-count checks, coercing
an empty SKU to five stars, reintroducing the Supabase client, and dropping the fail-open
catch each fail it.

### Shipped HTML is queried with a parser

`tools/html-query.mjs` wraps parse5 — a devDependency since `a269b45b`, referenced nowhere
until now — with `findAll` by tag, class and attribute, entity-decoded text, and `rawOf` for
exact source bytes via parse5's source locations. Both guard tests added this session moved
onto it. Re-proved after the rewrite: removing a card, drifting card text, deleting the
operating section, pointing an image at a root-absolute path, and altering an operating row
each fail.

## Traps this session paid for

**Six of my own findings were harness bugs, and two more nearly were.** A wrong R2 prefix
produced two "404 on production" images that were fine — the live path is
`media.masest.co/site/img/...`, note the `/site/`. A depth walk that started mid-attribute
reported one card per grid. A `PRODUCT_CATALOG_COPY` parser broke on quoted keys like
`"cr-hd"` and invented missing copy. A diff classifier called an edited file unchanged. An
overlap probe sliced to end-of-file and double-counted links. **Import the module; do not
scrape the source.** Every durable guard test passed its mutation checks; every bug was in a
throwaway probe that got no verification because it felt cheap.

**`git checkout -- .` destroys uncommitted work you meant to keep.** It was run to revert
`seo-inject`'s output while a rewrite of `tools/build-reviews.mjs` was uncommitted, and wiped
the rewrite. Commit first, or revert the named files.

**`npm run seo-inject` fires `preseo-inject`**, which reruns `build-reviews.mjs` and overwrites
any hand-written `data/reviews.json` fixture. Call `node tools/seo-inject.mjs` directly to
test the generator. It also rewrites `sitemap.xml` lastmod dates, so never run it with a
dirty tree.

**`execFileSync` blocks the event loop.** A test that spawns a tool synchronously while its
stub HTTP server runs in the same process will hang every request until the tool's timeout,
and fail against working code. Use `promisify(execFile)`.

**A secret can be approved and still be wrong to add.** The owner approved the service-role
secret; the suite then showed the architecture bans it. Read the deploy guards before wiring
credentials, and when a guard contradicts an approval, stop and ask — the approval was for
the action, not for overturning the boundary.

**A non-greedy regex cannot close an element whose children nest the same tag.** Use
`tools/html-query.mjs`.

**Only 8 product image binaries are tracked in the repo**, all marine. Every other jug lives
in R2, so a locally served page shows missing images and that is not a defect.

**The checkout email input is `#checkoutEmail`, not `#email`.** A silent `fill` miss cost a
30-second run that looked exactly like a rate-fetch hang.

**Two audit claims about checkout were simply wrong.** The wait was already announced, the
status line sits directly above the button and scrolls into view on submit, and
`#shippingSuiteToggle` was wired the whole time.

**This worktree has no `graft/` index**, although `AGENTS.md` in the main checkout describes
one. Do not assume graft tools answer for the worktree.

## Methods worth reusing

**A/B the branch against the live page.** `page.route(/\/js\/checkout\.js/)` serving the
branch file with its new `?v=` token rewritten to the **deployed** token so sibling imports
still resolve, plus a `route.fulfill` stub of a captured production response.

**Registry coverage.** Import the data, walk every string field, and check whether its first
seven words reach the rendered page. Found both unrendered registry blocks.

**Mutation-test anything whose number you report.** Break the input on purpose, confirm the
check fails, restore, confirm it passes. It is what separated this session's real findings
from its harness bugs.
