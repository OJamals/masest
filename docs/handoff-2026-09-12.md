### Two checkout address errors, one of them a 502

Driven live against production:

| address | before |
|---|---|
| 1600 Pennsylvania Ave NW | 200, 12 rates, 4.8-5.4s |
| 350 Fifth Avenue (real building, no unit) | 422 `CONFIRM_ADD_SUBPREMISES` |
| 123 Main St, Brooklyn 11201 | **502 Bad gateway** |
| 100 Willoughby St + `Apt 4` | 200, 12 rates |

Google verdicts "123 Main St, Brooklyn NY 11201" as `ACCEPT` and returns it **without a
ZIP+4**; ShipStation then answers `/rates` with `400 Address not found`, which escaped as a
bare `ShipStationError`, missed the `CheckoutFulfillmentError` branch in
`functions/api/shipping-rates.js:58`, and returned 502 — **which Cloudflare replaces with
its own HTML page**. The buyer read "No shipping option is available for this address and
cart": a typo in a street number told them MASEST does not deliver to them.

The apartment case is the reported one, and Google names the remedy in
`possible_next_action`. The client discarded it. It now names the field and opens and
focuses it.

Phase split, timed against the real providers: Google validation **141-325ms**, ShipStation
carrier list **1.2-1.6s**, the rate call the remaining ~3s.

## Traps this session paid for

**Six of my own findings were harness bugs. Verify the harness before reporting a defect.**
A wrong R2 prefix produced two "404 on production" images that were fine — the live path is
`media.masest.co/site/img/...`, note the `/site/`. A depth walk that started mid-attribute
reported one card per grid. A `PRODUCT_CATALOG_COPY` parser broke on quoted keys like
`"cr-hd"` and invented missing copy. A diff classifier called an edited file unchanged. An
overlap probe sliced to end-of-file and double-counted links. **Import the module; do not
scrape the source.**

**A non-greedy regex cannot close an element whose children nest the same tag.**
`<div ...>[\s\S]*?</div>\s*</div>` closes on the first inner `</div>`. Walk the tags and
match depth.

**Only 8 product image binaries are tracked in the repo**, all marine. Every other jug lives
in R2, so a locally served page shows missing images and that is not a defect.

**The checkout email input is `#checkoutEmail`, not `#email`.** A silent `fill` miss cost a
30-second run that looked exactly like a rate-fetch hang.

**`npm run seo-inject` rewrites `sitemap.xml` lastmod dates.** Do not run it with a dirty
tree.

**Two audit claims about checkout were simply wrong.** The wait was already announced, with
button copy and a status line naming Google and ShipEngine, and the page scrolls it into
view on submit. `#shippingSuiteToggle` was wired the whole time. The defects were in what
happened when the response came back.

## Method worth reusing: A/B the branch against the live page

`page.route(/\/js\/checkout\.js/)` serving the branch file with its new `?v=` token
rewritten to the **deployed** token so sibling imports still resolve, plus a `route.fulfill`
stub of a captured production response. Production left the suite field closed with generic
copy; the branch opened it with focus in `#shippingAddress2`. The same harness proved the
staged status copy does not clobber a fast error.
