## What shipped, with the numbers

### `/services` — the gap from the last handoff is closed, and the cause was not fonts

The previous handoff said the heading was the LCP element and something unknown delayed
it. **The heading was not the LCP element.** `.hero-anim` ran `heroRise` with
`from { opacity: 0 }` and `animation-fill-mode: both`, so the h1's *first paint was fully
transparent*. Chromium records a text node's paint once and does not re-evaluate an
element whose first paint was invisible, so the heading never entered the candidate list
at all and LCP fell through to whatever small fragment painted later — a 2,160px² "4
service packages" badge, against a **32,370px²** heading it had skipped.

Production, iPhone 14 Pro, 4× CPU, 150ms/1.6Mbps, motion left ON, median of 5:

| page | before | after |
|---|---|---|
| `/services` | FCP 2044 → LCP 2748, gap **704ms** | **2044 / 2044, gap 0** |
| `/services/water-analysis` | FCP 1812 → LCP 2440, gap **628ms** | **1864 / 1864, gap 0** |

`hero-anim` appeared on exactly 9 pages — `services.html` plus 8 guides generated by
`tools/seo-inject.mjs` — and those were the only 9 pages on the site with a gap. The
homepage has no hero entrance animation and its gap was already 0.

**This is why the `satoshi-07` preload only moved the gap 916 → 704ms.** It made the page
faster in general but could never restore candidacy, because the disqualification is about
paint opacity, not fonts. A partial improvement from an unrelated change is not evidence
the cause has been found.

Fix: `hero-anim` moved off the wrapper onto each **sibling** of the h1, no delay classes
added, so the entrance motion is unchanged and only the heading is static. The owner chose
to keep the animation rather than delete it. Keep the wrapper bare.

### `/cart` — the site's worst layout instability, and nothing saw it

`#cartLines` ships empty and `.cart-summary` ships hidden, so the page painted a short
"Loading cart details…" card then swapped in N full lines **and** revealed the summary
together when `/api/products` resolved at ~1.44s. One shift, `FOOTER y:453 → off-screen`.

Before, on production:

| cart | CLS |
|---|---|
| empty (control) | 0.0001 |
| one line | **0.4967** iPad Mini, **0.4796** Pixel 7, 0.3386 iPhone 14 Pro |
| three lines | **0.5578** |

It scaled with what the buyer intended to spend, on the page one tap before checkout.
**2,940 unit tests and 143 Playwright tests were green throughout** — nothing in this repo
sees layout instability unless a test is written to.

After, on production: **iPad Mini 0.1271 (−74%), Pixel 7 0.0808 (−83%)**.

> **Correction worth carrying forward.** Commit `a4eb9789`'s subject says "CLS 0.50 → 0.06".
> That 0.06 was the **local** figure. Production is 0.1271 / 0.0808. The local static server
> has no pricing data so the estimate block never populates there. The mechanism and the
> direction hold; that headline number in the commit message is optimistic.

Fix: a **synchronous inline script** — not a module, a module is deferred and lands a frame
late — reads `masest_cart` at parse time and stamps skeleton rows carrying `.cart-line`
itself, so every padding, grid and fixed-media rule applies unchanged.

**A fixed px reserve could never have worked.** Measured line heights run 132px (iPad Mini)
to 241px (iPhone SE), and differ by 19px *within one viewport* when a name wraps. Post-fix
per-line delta on hydration is **0px** at every viewport tried.

### `/checkout` — the pay button was unreachable at the moment it became clickable

Revealing the rate list grows the page ~860px, which put `#checkoutPay` off-screen on all
five devices measured — iPhone SE through a 1440px laptop, every one reporting
`inView: false`. The status line read "Continue to secure payment" while the button it
named was below the fold with nothing bringing it there.

`renderRates()` now scrolls the rate list into view and moves focus to the **selected rate**
rather than the pay button: the buyer's next decision is which service to use, and it puts a
screen reader at the top of the new content instead of past it. It has a single caller, so
it runs once per fetch and cannot steal focus while the buyer compares options.

**Deliberately not solved by reserving space.** That parks ~860px of void above the fold
before the buyer has asked for anything, pushes the address form down, and leaves the button
exactly as unreachable. Post-rates CLS of 0.07–0.20 is accepted as the cost of a reveal the
buyer requested, and recorded as such in the code.

## Purchase path — measured end to end, stopping at the pay button

Driven for real on production across five device descriptors: real `/api/products`, real
`/api/shipping-rates`, real rate selection, form filled, pay button enabled. **`#checkoutPay`
was never clicked.**

**Production is live-Stripe only and there is no test-mode path.** `js/config.js` ships
`pk_live_…`; `functions/_lib/stripe-runtime.js:28` forces live mode for host `masest.co`
**independent of the env var**; `/api/checkout` fails closed with `stripe_live_mode_required`
on a test key. Clicking pay opens a **live** Checkout Session. Nothing in the repo documents
a safe test purchase. The owner's standing decision is: do not click it.

**Neither `/api/shipping-rates` nor `/api/checkout` writes anything locally** — no `insert`
or `upsert` in either, nor in `checkout-shipping.js`. The order row appears only when the
webhook fires on real payment. So the entire path up to the button can be driven for free.

What works: blank submit reports all 8 fields individually plus a summary line (the previous
session's `reportValidity` fix holds on production); pay starts disabled and enables only on
a real rate; rates return 8 carrier options with dates and a "Lowest rate" marker.

## Traps this session paid for

**`page.waitForFunction(fn, options)` silently ignores the options.** The signature is
`(fn, arg, options)`; passing `{timeout}` second makes it the *payload* and the call falls
back to the 30s default. It produced an identical ~30,000ms "timeout" on all five devices,
which was reported as a site defect before being caught. **Identical numbers across
different configurations means suspect the harness** — the same tell as `route.fulfill` in
the previous session.

**The cart keys on the VARIANT sku (`vsku`), never the base product sku.** `/api/products`
returns base products (`cr`, `hcr`) each holding `product_variants[]` with the real
purchasable `vsku` (`CRCIP-1G`, `HCRCIP-25G`). Seeding a base sku earns a correct 409
`shipping_product_unavailable`, which looked exactly like a silent UI failure — until the
message turned up at `js/checkout.js:80` and the error selectors turned out to have missed
`#checkoutStatus`. **Two separate mistakes of my own stacked into one convincing false
finding.** Verify your own harness before reporting a defect.

**`networkidle` never settles on `/cart`.** Chat, tracking and image requests keep it busy
past 45s. Wait on the thing under test — here, skeleton rows replaced by real ones.

**`npm run serve` shells into `npm run build`**, which is the CMS-stripping trap. To serve
the tree for measurement, run `python3 -m http.server` against the source directly. Killed
mid-flight this session with no damage, because the checked-in content snapshot was current.

**`components.css` IS versioned now** (`?v=`), contradicting an older memory note saying it
was not. So is `js/checkout.js`. Check the file, do not recall.

**Playwright's 30s per-test timeout overrides a longer per-navigation timeout.** A test that
deliberately delays work needs `test.setTimeout()`, not a bigger `goto` timeout.

**The shadow freeze allowlist is a ratchet, not a ruling.** `tests/surface-shadow-freeze`
says in its own header that removing an entry when a literal is tokenised is "always safe and
encouraged". Read a guard test's stated intent before treating it as a decision you would be
contradicting — this one was nearly escalated to the owner as a conflict when it was not one.

**A test can encode a decision and a mechanism in the same block.**
`tests/cart-page.test.mjs` pinned both "no raw SKU before the catalog resolves" (a real
decision — honoured; the SKU came out of the skeleton) and "wait for the loading card" (a
mechanism, changed with owner approval). Separate the two before proposing an edit.

**Gate the mechanism as well as the outcome.** A CLS assertion against the local server
passes with the fix deleted, because `/api/products` 404s instantly and the swap lands before
first paint. `tools/homepage-vitals.spec.mjs` holds the catalog open with `route.continue()`;
`tests/cart-reserve-contract.test.mjs` asserts the mechanism, including that the inline script
and `js/cart.js` still agree on the storage key. An outcome-only gate goes quietly green when
the thing it guards stops running.

**`.eyebrow` is `inline-flex`, so it has no line-height floor.** Unlike a block `h2` or `p`
it collapses to its tallest child — a 9px bar instead of 20px of text. A zero-width space
restores the font's own metrics without a magic pixel value.
