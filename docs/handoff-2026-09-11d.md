others rendered 72–80px — cart, checkout and order-confirmed among the ten. Measured at
1440px across 20 pages: **15 now share one size, against 5 before**; at 320px, 14 share one.

inline every style because mail clients strip stylesheets, and they load none of the site's

### `/products`

## Traps this session paid for

**A `<style>` injected at runtime beats every linked stylesheet.** `js/account-nav.js`
appends one carrying `.nav-cart { width:42px }`. `css/style.css` already had
`.nav-cart { min-width: 44px }` **twice** and the button still rendered 42px — one copy was
also cancelled by `min-width: 0` in `css/navigation.css`. Ask the browser which rule wins
(`CSS.getMatchedStylesForNode`; `.qa-local/frontdoor/why-nav-cart.mjs`). Any sizing or
tap-target gate must measure **rendered boxes**.

**A shadowed declaration is not a dead rule.** An audit reported `css/style.css:304`
`.display` as "DEAD everywhere, confirmed via matched-rules" and recommended deleting it.
Only its `font-size` was shadowed; the same block still supplies `min-width`,
`overflow-wrap`, `font-weight`, `letter-spacing` and `line-height`, and
`overflow-wrap: anywhere` is what keeps long headlines inside their container. Deleting the
block would have changed every heading on the site.

**Do not run the Playwright suites while Playwright subagents are live.**
`admin-crm-workspace.spec.mjs:60` — a race-condition test — failed twice under that load and
passed 3/3 in isolation and 62/62 once the agents finished. It looked exactly like a
regression.

**Measure against a priced catalog.** The local tree has no prices, so a `/products` card
renders ~90px shorter than the real one. Half an hour went into optimising a card that does
not exist before the harness was pointed at production's own `/api/products` payload.

**A naive above-the-fold count lies on mobile.** `top < innerHeight` counted nine collapsed
cards sitting at a zero rect as visible. Filter on a real box first. My own reported "9/15
on Pixel 7" was wrong for this reason; the true baseline was 0/15 everywhere.

**Re-derive an inventory before carrying its number forward.** "15 occurrences, 7 documents,
2 printed labels" was repeated for four sessions from a prior doc. Extracting the PDFs gives
**10 across 6 documents and 1 printed label**; most "Safe on …" hits in the library are
material-compatibility claims that were never part of it.

**A guard test can be wrong in the same commit that adds it.** The first
`robots-crawl-preferences` assertion banned the string `Google-Extended` anywhere in the
file, including the comment explaining why it is allowed. Parsers ignore comments; the
explanation is worth more than the theoretical confusion.

### Reported but disproven — do not action

- *"robots.txt blocks every AI crawler, no answer engine can read the site."* The blocked
  agents are training crawlers; `OAI-SearchBot`, `ChatGPT-User` and `PerplexityBot` were
  never blocked.
- *"Zero Product/Offer JSON-LD anywhere."* All product pages carry it; the problem is
  contamination, not absence.
- *"`shipping_rate` is a dead content type."* It has no declared snapshot/runtime delivery,
  which is a real registry inconsistency, but it is consumed through a Stripe path.
- *"Grid cards carry no description."* They carry a one-line application descriptor
  (`.shop-card-type`); what is dropped is the longer summary.
